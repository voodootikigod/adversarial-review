# T7 — `--loop` for branch scope (pre-merge convergence loops)

## Problem

`--loop` rejects `--scope branch` and `--base` (src/loop.js `runLoop` scope
block). The working-tree loop's fixer writes uncommitted changes and checkpoints
with `git stash` — a model that only works for working-tree review. So `--loop`
cannot drive the most common real use case: review a feature branch vs its base,
apply fixes **as commits on the branch**, re-review until clean (ADR-0007's
18-round Cursor case study was driven manually for exactly this gap).

## Approved design frame (owner sign-off)

The loop touches **only the current feature branch**; the base (usually `main`)
is **read-only** — a diff reference, never a write target. Rollback uses
`git reset --hard` **on the feature branch**, approved precisely because it never
rewrites `main`. Acceptable even if the feature branch is pushed (warn, don't
refuse).

## Approach — a separate `runBranchLoop`, not a refactor

Add `export async function runBranchLoop(cwd, args)`. `runLoop` dispatches to it
when `args.scope === "branch" || args.base` (replacing the two error blocks); the
rest of `runLoop` (the working-tree path) is **unchanged** — zero regression risk.
`runBranchLoop` reuses the existing leaf helpers: `detectFixer`,
`probeOsConstraint`, single-provider `runReview` / `runProviderRound`,
`getGatingFindings`, `gatingSetsEqual`, `getFixFiles`, `buildFixPrompt`,
`redactSecretsInFindings`, `spawnFixer`, `buildLoopSummary`, `emitEvent`.

## Branch-loop mechanics (contract)

1. **Clean-tree precondition.** At start, `git status --porcelain` must be empty;
   otherwise error (exit 1) and do nothing. This is the safety keystone: any file
   that appears mid-loop is fixer-created, so `git add -A` / `reset --hard` /
   `clean -fd` can never touch the user's pre-existing work.
2. **Base + checkpoint.** Resolve base as `collectReviewContext` does (`args.base`,
   else upstream → origin/HEAD → main). `originalHead = git rev-parse HEAD` is the
   whole-loop recovery target. Refuse a detached HEAD (exit 1). Capture
   `baseSha = git rev-parse <base>` once for the AC5 invariant.
3. **Round review.** `collectReviewContext(cwd, { scope: "branch", base, ... })`;
   compute `gatings` exactly like the working-tree loop (single or `--providers`
   quorum path).
4. **Clean** → exit 0; fix commits stay. **no-progress** (gating set repeats a
   prior round) / **ceiling** (`--loop-max` reached) → exit 2, **leave** the fix
   commits (partial progress) and print `git reset --hard <originalHead>` recovery.
5. **Fix step.** `beforeFixHead = git rev-parse HEAD`; spawn the fixer (writes the
   working tree).
   - fixer error/timeout → `git reset --hard <beforeFixHead>` then `git clean -fd`
     (discard the failed partial), exit 2; prior commits remain; print recovery.
   - fixer made no change (working tree still clean) → no-diff, exit 2, recovery.
   - fixer made changes → `git add -A` then
     `git commit -m "fix: resolve adversarial-review findings (round N)"`; that
     commit is the branch progress the next round re-reviews.
6. **SIGINT** → kill the fixer, print `originalHead` + the reset recovery, exit 1.
   **Never auto-reset on interrupt** — the human decides.
7. **Pushed branch** → if the branch has an upstream, warn that a reset will
   diverge local from remote (force-push needed to reconcile); proceed.
8. **Events** → same NDJSON events + terminal `loop_summary`, with a
   `checkpoint`/`originalHead` field instead of `stashRef`.

## Out of scope

- Squashing/amending the fix commits (left individual; user squash-merges).
- Scratch-worktree strategy (reset-on-branch is the approved model).
- Auto force-push; `--input` + branch-loop; writing to `main` under any path.

## Acceptance criteria

- **AC1 (dispatch + clean-tree precondition)** — verified by `node --test test/branch-loop.test.mjs`:
  `--loop --scope branch` (and `--loop --base <ref>`) routes to `runBranchLoop`; a
  DIRTY working tree at start exits 1 and creates no commit and moves no ref.

- **AC2 (converge = append commits, base untouched)** — verified by `node --test test/branch-loop.test.mjs`:
  a committed branch with a fixable finding + a fixer that resolves it → the loop
  commits the fix on the branch and the re-review approves (exit 0); HEAD advanced
  by ≥1 commit; the base ref's sha is unchanged.

- **AC3 (fixer error rolls back this round only)** — verified by `node --test test/branch-loop.test.mjs`:
  a fixer that writes a partial change then exits non-zero → `reset --hard` to
  `beforeFixHead` + `clean -fd`, exit 2, no partial commit remains, base ref
  unchanged.

- **AC4 (no-progress/ceiling leave commits + recovery)** — verified by `node --test test/branch-loop.test.mjs`:
  a reviewer that keeps flagging + a fixer that commits each round → exit 2 with
  exitReason `no-progress` or `ceiling`, the fix commits REMAIN, and a
  `git reset --hard <originalHead>` recovery line is printed to stderr.

- **AC5 (base/main is never a write target)** — verified by `node --test test/branch-loop.test.mjs`:
  across the clean, no-diff, fixer-error, and no-progress/ceiling exits, the base
  branch's sha is byte-identical before and after the loop.

- **AC6 (loop_summary parity)** — verified by `node --test test/branch-loop.test.mjs`:
  under `--json`, the terminal NDJSON line is a `loop_summary` with
  `providers/iterations/verdict/exitReason/survivingCount/acceptedCount`.

- **AC7 (working-tree loop unchanged)** — verified by `npm test`: the existing
  working-tree loop tests (`test/loop-summary.test.mjs`,
  `test/loop-providers.test.mjs` — frozen rails) still pass; whole suite green.

- **AC8 (mutation-proven, one-time manual)** — verified by re-running `node --test test/branch-loop.test.mjs` after each mutation:
  (i) drop the clean-tree precondition → AC1 fails; (ii) reset to the base ref
  instead of `beforeFixHead`/`originalHead` → AC3/AC5 fail; (iii) commit onto the
  base ref instead of the feature branch → AC5 fails.

## Risks / things a build agent must not do

- NEVER check out, commit onto, reset, or otherwise move the **base** ref. The
  base is resolved to a sha and only ever read/diffed.
- Do not run `git clean` without the clean-tree precondition — it could delete the
  user's untracked files. The precondition is load-bearing for `clean -fd` safety.
- Do not auto-reset on SIGINT; print recovery and exit.
- Do not touch the working-tree `runLoop` body below the dispatch.
- `git reset --hard` targets are always `beforeFixHead` (this round) or
  `originalHead` (whole loop) — never a ref name, never `HEAD~n` arithmetic.

## P1 interrogation resolutions (premortem + parallax, self-answered)

- **R1 (separate fn vs refactor)** — Separate `runBranchLoop`. The checkpoint
  mechanics (commit/reset vs stash/pop) and change detection (branch-diff vs
  working-tree dirty) differ enough that a shared abstraction would entangle and
  risk the shipped working-tree loop. Duplicated skeleton is the cheaper risk.
- **R2 (clean-tree precondition is mandatory)** — Without it, `git add -A` would
  sweep the user's unrelated uncommitted work into a "fix" commit, and `clean -fd`
  could delete their untracked files. Refusing a dirty start is the only safe base.
- **R3 (when to reset vs leave commits)** — Reset ONLY on a failed/partial fix
  (fixer error/timeout) → back to `beforeFixHead`. no-progress/ceiling/no-diff
  LEAVE the commits (they are real progress) and only PRINT the whole-loop reset
  recovery; the human chooses whether to unwind. Clean leaves everything (success).
- **R4 (base invariant is the core safety test)** — AC5 asserts the base sha is
  unchanged on every path; this is the machine-checkable form of "never rewrites
  main". A mutation that commits/resets the base ref must fail a shipped test.
- **R5 (detached HEAD / pushed branch)** — detached HEAD is refused (no branch to
  advance). A pushed branch is warned-not-refused per owner sign-off.
