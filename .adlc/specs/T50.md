# Spec T50: Parity suite harness (ROADMAP step 0)

Status: P1 draft (2026-10-06). The ticket body below is the source of truth for scope, rails and acceptance criteria. The section "Resolved implementation decisions" pins the choices that three independent parallax readings diverged on. Where it is more specific than the ticket, it wins.

## Resolved implementation decisions (parallax round 1)

1. **Module layout.** Exactly the ticket's scope files. `test/parity/helpers/harness.mjs` is the single public entry that rows import; it re-exports mock-cli, http-stub, mutant and rows helpers. No other helper module is created (rails-guard enforces scope).
2. **Stub API.** `createStub()` (async) returns `{ port, base(provider), enqueue(provider, reply), requests, unexpected, assertNoUnexpected(), close() }`; `providerEnv(stub, provider)` returns `{ <PROVIDER>_BASE_URL, <dummy key var> }`. Reply builders: `anthropicReply`, `openaiReply`, `geminiReply`, `rawReply`.
3. **Mock response storage.** Each queued response is written as files under `<mocksDir>/.<name>.d/<n>/` (stdout, stderr, exit, sleep, marker, writeFiles manifest), which the `#!/bin/sh` script reads with `cat` by absolute path. Nothing is embedded via heredoc.
4. **Records scope.** `makeContext()` creates a per-row context owning the repo-sibling `mocksDir`, `sysbinDir` and `records/` dirs. `runCli(args, { ctx, ... })` reuses them across calls in one row, while HOME, TMPDIR, XDG_CONFIG_HOME and configDir are fresh per call. `ctx.records(name)` returns ordered `[{ n, argv, stdin, env }]` without probes, and `ctx.probes(name)` returns the probes. A probe is exactly one argument that is `--version`, `-h` or `--help`.
5. **Lenient parsing.** `run.json` and `run.events` are `undefined` when stdout is not valid JSON or NDJSON, and `run.jsonError` holds the parse error. `runCli` never throws on output shape (failure rows print non-JSON).
6. **Envelope comparison (34/35).** HEAD and BASE stdout lines are paired 1:1 by index. Only lines whose parsed `type` is `loop_summary` are compared structurally, after deleting the envelope key from HEAD (for 35, only when its value is `null`). Every other line must be byte-identical after normalization. Envelope 36 removes exactly one HEAD stderr line containing `adversarial-review setup` on a detecting run; BASE must have no such line, and the rest must be byte-identical.
7. **SMOKE-LOOP argv** is `--loop --loop-unsafe --json --provider anthropic` plus the fixer selection flag the existing loop tests use. It does NOT add `--allow-secrets` (the fixture contains no secret; the smallest argv keeps captures honest).
8. **Capture counter** is per process, keyed by (absolute dir, rowId). `node --test` runs each file in its own process and row ids are unique per file, so indices cannot collide.

Other choices all three readings agreed on are adopted as stated in the ticket: spawn rather than spawnSync, an env built from scratch, mocks exiting 97 when their queue is exhausted, capture-compare exits 0/1/2 with both trees' manifests validated first, the normalization token set, and the win32 skip.

## Premortem decisions (interrogation round 2, 2026-10-06; binding, extend the ticket's ACs)

Each item below adds acceptance criteria (APn). Where an item contradicts ticket text, the item wins.

AP1 Provider-bound payloads are compared. Captures gain two COMPARED fields. `prompts` holds, for every non-probe mock invocation in call order, `{ mock, n, argv, stdin }`. `requests` holds, for every stub request in arrival order, `{ provider, path, body }` (prefix-relative path; body as received). Both are normalized with n1-n6 (n4 covers fence nonces). Tag semantics (9b) now count `prompts` and `requests` as compared fields, so deltas 9, 14, 15, 17 and 29 must be tagged on rows whose payload they change. Verified in harness.test.mjs with synthetic trees. A one-character change to a `prompts[0].stdin` exits 1 naming the row and field `prompts`. A one-character change to `requests[0].body` exits 1 naming `requests`. A nonce-only difference inside a fence in `prompts` exits 0 (positive control).

AP2 Normalization n6, and a Node-version guard. n6 removes exactly these stderr lines: `(node:<pid>) ExperimentalWarning: The Fetch API is an experimental feature. This feature could change at any time` and the following `(Use \`node --trace-warnings ...\` to show where the warning was created)` line, when present. No other warning line is removed. Captures record `node: process.version`. capture-compare exits 2, naming both versions, when BASE and HEAD captures differ in Node MAJOR. Verified with synthetic captures. (a) Two captures differing only by the n6 lines -> exit 0. (b) Negative control: a different ExperimentalWarning line (for example one about `--experimental-vm-modules`) is NOT removed -> exit 1. (c) Negative control: BASE node v18.x, HEAD v22.x -> exit 2. The SMOKE-API row run on the CI matrix produces n6-normalized stderr that is byte-identical across legs, checked by a new `parity-cross-node` job in .github/workflows/ci.yml. Each matrix leg uploads its SMOKE-API capture (PARITY_CAPTURE) as an artifact. The job, which `needs` the matrix, runs `capture-compare --field stderr --cross-node` pairwise over the legs and fails on any difference. `--cross-node` is the only mode that waives the Node-major guard, and it compares only the named field. No existing CI job changes.

AP3 Tag scope. Each DELTAS entry gains `fields`: the compared fields the delta may change. Pinned values: 1 ["argv","stderr"]; 8 ["stdout","prompts","requests"]; 9 ["stdout","prompts","requests"]; 14 ["prompts","requests"]; 15 ["requests","prompts","stdout","stderr"]; 17 ["stderr","code","stdout"]; 31 ["prompts","requests"]. All others ["argv","code","stdout","stderr","gitState","calls","prompts","requests"] until their landing ticket's P1 narrows them (narrowing is an amendment the landing ticket may make to deltas.mjs in its landing commit, recorded in the PR). A row tagged for n may differ ONLY in delta n's `fields`; a difference in any other compared field exits 1 naming the field. For every tagged-and-allowed row, capture-compare prints the normalized unified diff of each differing field, which the P5 reviewer must read. Verified with synthetic trees: tagged-for-8 row differing in stdout -> exit 0 and the diff printed; the same row also differing in `code` -> exit 1 naming `code`.

AP4 preResolution is cross-checked. assertStderrExact throws `preResolution declared but the run reached a provider` when a run declaring preResolution has any non-probe mock invocation or any stub request. It throws `preResolution is invalid with --loop` when argv contains `--loop`. Verified in harness.test.mjs: the usage-error run with the declaration does not throw; the same declaration on SMOKE-CLI (which calls the claude mock) throws; a declaration on an argv containing --loop throws.

AP5 Event alignment and gated --allow. In capture-compare, stdout NDJSON events are paired by (type, ordinal within that type), not by line index. An event present in only one side is reported as a single finding `INSERTED <type>#<k>` or `REMOVED <type>#<k>`. Envelope checks (34/35) operate on the paired `loop_summary` events. `--allow <ids>` requires `--allow-reason "<text>"` (otherwise exit 2), echoes `ALLOWED <rowId>: <reason>` in the report, and is refused (exit 2) for a row tagged for the delta under `--delta`. Verified with synthetic trees: HEAD inserts one `progress` event before `loop_summary` -> exactly one INSERTED finding and no other diff lines; `--allow X` without a reason -> exit 2; `--allow X --allow-reason r` on an untagged differing row -> exit 0 with the ALLOWED line; `--allow` on a row tagged for the `--delta` -> exit 2.

AP6 Network recording covers http/https and stays consistent. fetch-recorder.cjs also wraps `http.request`, `http.get`, `https.request` and `https.get`, and records `{ api, url }`. withFetchRecorder asserts, for every recorded run, that the number of recorded requests to the stub is at least the stub's request count for that run, and throws `network recorder missed traffic` otherwise. Verified in harness.test.mjs. (a) SMOKE-API records the stub URL via fetch. (b) A direct child script doing `https.request` to a second local server's port is recorded with api `https.request`. (c) Negative control: with the http hook disabled by a test-only env var, case (b) makes assertOnlyStubUrls fail through the consistency check instead of passing vacuously.

AP7 Pinned git env and a nondeterminism sweep. The hermetic env pins `GIT_CONFIG_GLOBAL=<HOME>/.gitconfig`, written with init.defaultBranch=main, advice.detachedHead=false, advice.statusHints=false, core.pager=cat, color.ui=false. It also sets `GIT_CONFIG_NOSYSTEM=1`. A sweep test (harness.test.mjs, describe 'nondeterminism sweep') captures each of these shapes twice in independent runs and requires capture-compare exit 0 on the pair: auto-detected provider (writes the config cache with resolvedAt), `--findings-ledger` run, a claude-mock 5xx-then-success retry, a SIGINT loop (via the FIFO handshake, AP8), and `--prompt-only`. A per-run value found by the sweep is handled now by a new rule with controls; resolvedAt lives only in the config file, which is not a compared field, so it needs no rule unless the sweep shows it elsewhere. Verified: the sweep describe passes; a negative control removes the git pinning and the fresh-HOME `hint:` lines make the pair differ.

AP8 FIFO handshakes and no CI skips. Mocks never `sleep` for synchronization. A response may declare `waitFifo: <name>`: the mock writes its marker, then blocks reading a named pipe (mkfifo) under the context dir until the test writes to it. runCli's signalAfter waits for the marker, sends the signal, then releases the FIFO. A guard test fails if any test/parity file contains `process.env.CI` in a skip condition or `.skip(` on a row. Verified: a SIGINT smoke check using the FIFO runs 20 times in a loop inside harness.test.mjs with identical outcomes; the guard test fails on an injected file containing `skip: process.env.CI`.

AP9 Mutant integrity. withMutant copies the whole package (the output of `git ls-files` minus `test/`) into the temp dir. It injects, into the mutated file, a sentinel line that writes `<tmp>/.mutant-loaded` when the module is evaluated. After `fn` returns, it throws `mutant was not loaded` unless the marker exists. Policy, stated in mutant.mjs's header: a refactor ticket may not edit any mutant's `find` text, and a stale mutant is re-targeted in a separate commit under its own approved ticket before the refactor merges. Enforcement: every refactor or delta ticket (T55 and later) declares `test/parity/**` as rails, so `adlc rails-guard --base main --ticket <id>` exits 2 on such an edit. Staleness is detected here: a harness test asserts that every mutant registered in test/parity (exported `MUTANTS` lists) has a `find` that occurs exactly once in its target file at HEAD, and fails naming the mutant otherwise. Negative control: an injected mutant with a non-matching find fails that test. Verified: the AC6 mutant creates the marker; a negative control pointing withMutant at a file the CLI never imports throws `mutant was not loaded`.

## Round 3 resolutions (parallax re-read, converged)

- The AP items supersede ticket item 8 (the mutant copy list), the field lists in 9b and 11, and resolved decision 6. NDJSON events pair by (type, ordinal); lines that are not JSON events pair by index among themselves, byte-exact after normalization; a single-object non-loop `--json` stdout is compared whole.
- `prompts` holds the non-probe invocations recorded DURING that runCli call (above the call's starting counter), in global order via a per-context sequence counter; each entry keeps its per-mock `n`. `requests` holds the stub requests added during that call, with the raw body string. n1-n5 apply to every string leaf of argv, stdout, stderr, gitState, prompts and requests; n6 applies to top-level stderr only.
- n6 regex: `^\(node:\d+\) ExperimentalWarning: The Fetch API is an experimental feature\. This feature could change at any time$`, plus the next line only if it starts with "(Use `node --trace-warnings". It is emitted on Node 18 and 20 only.
- A missing `node` field in a capture exits 2. The Node-major check runs before any row comparison.
- Tag scope: tagged-for-n requires all three conditions of item 11. Fields come from HEAD's deltas.mjs. A landing ticket may NARROW its own delta's fields and never widen them (widening needs a P0 amendment to T50). The envelope is stripped first, then the fields scope applies. INSERTED/REMOVED event findings count against `stdout`. Tags grant nothing without `--delta`.
- `--allow`: one `--allow-reason` covers all listed ids; it is refused on a row tagged for the active `--delta`; for an allowed row only the `ALLOWED <rowId>: <reason>` line is mandatory, while unified diffs are mandatory for tagged rows.
- AP4 order: an empty preResolution string throws TypeError; then the `--loop` check; then the provider-contact check (non-probe mock records or stub requests, including 418 unexpected, added during that call).
- AP6: the preload patches the module objects that `require('http')` and `require('https')` return, plus fetch. It writes NDJSON `{api,url}` with a reentrancy guard so https.get is not logged twice. `readFetchLog(run)` still returns URL strings (AC19) and `readNetLog(run)` returns the objects. Case (b) uses `https.request({ protocol: 'http:', agent: new http.Agent(), ... })` against a second createStub, which counts it, so the negative control cannot pass vacuously. The test-only disable var is `PARITY_NET_HOOK_DISABLE=http`.
- AP8: the fifo lives at `<ctx dir>/fifo/<name>` and is created with mkfifo from the host PATH (Linux coreutils, macOS /usr/bin). The mock touches its marker, then runs `cat "$fifo" >/dev/null`. The release opens the fifo with O_WRONLY|O_NONBLOCK, skips on ENXIO (mock already gone), writes one byte and closes. The marker wait polls every 10 ms with a 10 s deadline. `sleep` remains only for timeout rows, and a guard rejects sleep combined with signalAfter.
- AP9: copy the working-tree bytes of `git ls-files -z` minus test/, keeping executable modes. The sentinel is one line after the shebang (or at line 1), `(await import('node:fs')).writeFileSync(<abs marker>-<i>, '');`, inserted after the find/replace. Each mutated file has its own marker. The check runs before cleanup, and also when fn throws (the original error wins).

When `PARITY_CAPTURE=<dir>` is set, runCli (inside a row(), or with capture.rowId given; runs outside any row and without capture.rowId are never captured) writes `<dir>/<rowId>/<n>.json`, where <n> is a 1-based counter per (dir, rowId) in call order, so two trees pair captures by (rowId, n), containing `{ argv, envKeys, code, stdout, stderr, gitState, calls, roots, ports, preResolution }` with RAW (un-normalized) values, where calls = the per-mock invocation count and the stub request count by provider, roots = that run's temp-root paths (repo dir, mocksDir, sysbinDir, HOME, XDG_CONFIG_HOME, TMPDIR, and configDir = the parent directory of the config path; the harness creates configDir but never the config file, so first-run semantics are unchanged) and ports = the stub ports it used. On first write to `<dir>` the harness also writes `<dir>/_manifests/` = a copy of every test/parity/rows/*.json plus `landed.json` (LANDED_DELTAS); capture-compare reads the HEAD tree's `_manifests/` (never the working copy), so synthetic test trees inject manifests by writing that directory. Normalization happens IN capture-compare at COMPARE time, using each capture's own roots/ports (so a path that is not one of that run's recorded roots stays raw and differs), pinned HERE (not left to P1) and listed in the capture-compare.mjs header, applied to argv, stdout, stderr and gitState: (n1) each run's temp roots (repo dir, mocksDir, sysbinDir, HOME, XDG_CONFIG_HOME, TMPDIR, config path) -> fixed tokens; (n2) the stub port -> `<port>`; (n3) the loop stash timestamp `adversarial-review-loop-<digits>` (src/loop.js L986-987; it appears in the stdout `stash_created` event's stashName/recoveryCmd, in buildRecoveryCmd lines on stderr and in `git stash list`) -> `adversarial-review-loop-<ts>`; (n4) the 12-character base64url fence nonce of fenceUntrusted/fenceDirective (src/review.js L83, L132: `<token><label>:<nonce>>>>`, visible in --prompt-only stdout) -> `<nonce>`, matched ANYWHERE on a line but only where the nonce directly follows one of the four fence token constants and a label, i.e. the regex /(<<<(?:UNTRUSTED|END|DIRECTIVE|END_DIRECTIVE):[A-Z_]+:)[A-Za-z0-9_-]{12}(>>>)/g (fences can open mid-line: prompt-template.md L17-18 render `Target: <<<UNTRUSTED:TARGET_LABEL:<nonce>>>>` and `User focus: <<<DIRECTIVE:USER_FOCUS:<nonce>>>>`; amended at P0 2026-10-05); (n5) the raw-output dump name `adversarial-review-raw-<pid>-<ms>.txt` (src/review.js L451) -> `adversarial-review-raw-<pid>-<ts>.txt`. Nothing else is normalized: every extra rule is a blind spot in every later behavior-diff gate, so adding one needs a P0-approved amendment with its own AC17 controls. `test/parity/helpers/capture-compare.mjs <baseDir> <headDir> [--allow <ids>] [--delta <n>]` compares exactly these capture fields: argv, code, stdout, stderr, gitState and calls; roots, ports, envKeys (the sorted list of environment variable NAMES passed to the child, values never stored) and preResolution are metadata and are never compared. It exits 0 only if every row present in both trees is identical in the compared fields after normalization, or is in `--allow`, or (with `--delta n`) is tagged for n: its BASE manifest lists n, HEAD's `_manifests/landed.json` contains n (the landing commit landed it), and its HEAD manifest no longer lists n (house rule: the landing commit consumes the tag), or differs only by delta n's envelope (item 9c). A row present only in HEAD is reported as new and allowed; a row present only in BASE fails (a removed row needs `--allow`). The P5 behavior-diff gate of every later ticket runs it with `--delta <its delta>` against a base-worktree capture.
12. Exact-stderr guard for delta 36. harness.mjs exports assertStderrExact(run, expected) (equality; '' means empty). Called inside row() on a detecting run while 36 is not in LANDED_DELTAS, it throws unless the current row's futureDeltas lists 36: D9 says "Parity rows that assert stderr exactly list 36", and this makes the rule self-enforcing for every row ticket (T52, T53, T54, T80 and any other) instead of relying on a hand-made id list. Called outside row(), it throws. Rows that only check substrings use assertStderrIncludes / assertStderrExcludes and need no 36 (the envelope covers the hint). Signature: assertStderrExact(run, expected, { preResolution } = {}); a non-empty preResolution string exempts the run (DEFINITIONS, detecting run) and is recorded by REWRITING the run's capture file (run.capturePath, when the run was captured) to add `preResolution` so P5 reviewers can audit each declaration.

Fetch recorder (D10 'Parity' network check, provided now because the helpers are frozen for later tickets). test/parity/helpers/fetch-recorder.cjs is a CommonJS preload, loaded with `nodeArgs: ['--require', <abs path>]` (works on Node 18-24; `--import` would exclude Node < 18.19).
