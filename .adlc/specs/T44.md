# Spec T44: Implement Linux process confinement (Landlock/bubblewrap) for loop fixer execution

## Context & Problem
The `--loop` fixer currently runs provider CLIs with `--dangerously-skip-permissions` on a prompt derived from an untrusted diff. On Linux, previous implementations relied on `unshare --mount`, which creates a mount namespace without remounting directories read-only. Consequently, the fixer retained full write access to the filesystem (`~`, `~/.ssh`, shell profiles, `.git` internals, and other repositories).

Real write confinement requires Landlock LSM or `bubblewrap` (`bwrap`).

## Proposed Solution
Implement Linux process confinement for the loop fixer using `bubblewrap` (`bwrap`) or Landlock LSM:
1. Restrict filesystem write access for the fixer subprocess strictly to the temporary workspace / target working directory.
2. Deny write access to `~/`, `~/.ssh`, parent directories, and non-workspace repositories.
3. When `bwrap` (or Landlock) is detected on Linux, `--loop` executes securely without requiring `--loop-unsafe`.
4. If kernel write confinement is unavailable on Linux, require `--loop-unsafe` explicitly before proceeding.
