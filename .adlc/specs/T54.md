# Spec T54: --loop parity rows, working-tree and branch scope (ROADMAP step 0)

Status: P1 draft (2026-10-07). The ticket body below is authoritative. The sections above it pin parallax resolutions and, after the premortem, the premortem decisions; where they are more specific, they win. .adlc/specs/T50.md is binding for helpers and rules. .adlc/specs/T53.md conventions (leak sweep, NEG mutant proof, mock-side sequencing) are reused as stated below.

## Resolved implementation decisions (parallax round 1)

1. **Outcome-level pins (C1 compatibility).** Rows pin exit code, the exact ordered list of event types, named fields on events paired by type plus ordinal (T50 AP5), git state, and exact reviewer and fixer call counts. They do not pin code layout, stash names, timestamps or log wording beyond the pinned substrings. C1 must keep every row green with ZERO edits. The asymmetric scope fields are pinned deliberately: matchedIteration and stashRef on working-tree loop_end only, and originalHead on branch only. NOPROG-br asserts matchedIteration is ABSENT.
2. **Mutant staleness** follows T50 AP9: no ticket, C1 included, re-anchors a NEG mutant's find in its own change. Re-targeting is a separate approved commit.
3. **Shared conventions.** SUPERSEDED by AP10: T54 imports `assertNoTokenLeak` and `assertMutantRan` from test/parity/helpers/leak.mjs (a T50 helper). There is no local copy and no equality guard.
4. **Live-captured constants.** Values known only from a 2.11.1 run (the FIXER-EMPTIES review count, LOOP-MULTI provider labels, human-report lines, restore-path stderr) are committed in test/parity/fixtures/loop-2.11.1.json, and a test asserts every pinned constant appears in it.
5. **Driving terminal states** uses sequenced response queues. Reviewer stub and mock queues are consumed in call order, fixer actions run in the repo cwd, and an exhausted queue returns 418 (recorded in stub.unexpected, which every row asserts empty).
6. **Data safety (adopted, human decision 2026-10-07).**
   - **Pre-seeded user stash.** Every working-tree fixture creates one stash of the user's own before the run. Every working-tree row asserts it still exists, with the same `stash show -p` hash. After a clean exit the stash list equals exactly that user stash.
   - **Staged hunk.** FIXERR-wt, FIXTIMEOUT-wt and NOPROG-wt fixtures add a staged hunk on other.js and assert it is still staged afterwards.
   - **Rollback targets bytes.** FIXERR-wt and FIXTIMEOUT-wt assert code.js equals the user's PRE-FIX dirty bytes (not HEAD's). They pin through stderr which restore path 2.11.1 takes: `stash pop --index` or the per-file fallback.
   - **Retained checkpoint content.** NOPROG-wt, CEIL-wt and SIGINT-wt assert the stash named by loop_end.stashRef (or by the recovery command, which the test never runs) exists and that its `stash show -p` equals the pre-fix diff.
   - **Branch clean scope.** Branch fixtures add a gitignored file and a user untracked file outside the fixer's paths. FIXERR-br and FIXTIMEOUT-br assert both survive (this catches `clean -fdx` or an over-broad clean).
   - **New row LOOP-FIXERR-R2-br.** Fix 1 commits and fix 2 fails. It asserts HEAD equals fix 1's commit, not originalHead or main. Tags: the same as FIXERR-br.
   - **New mutants.** (f) createStashCheckpoint without the re-apply makes CONVERGE-wt fail (the user's change is gone). (g) The reset target at the first branch rollback site becomes originalHead, which makes FIXERR-R2-br fail. (d) also runs on FIXSECRETS-OFF-br.
   - **Fix-secrets surfaces.** FIXSECRETS-OFF asserts the token is absent from the fixer's argv, stdin and any prompt file. Both FIXSECRETS rows assert the reviewer API key value never reaches the fixer's argv or stdin. FIXSECRETS-ON allows the raw token only in the fixer's stdin.
7. **NEG rows** follow T53 AP10: a named failure signature plus the RAN marker from inside the mutated block.

## Premortem decisions (interrogation round 2, 2026-10-07; binding, extend the ticket's ACs)

## Round 3 resolutions (feasibility re-read and vacuousness audit, 2026-10-07; binding, override AP and ticket text)

R1 AP1 corrected to 2.11.1's real rollback (verified in a temp repo). createStashCheckpoint re-applies the stash, so the file is always dirty when the fixer edits it, `stash pop --index` always refuses, and 2.11.1 always takes the per-file fallback (`git checkout <stash> -- <file>`). That fallback writes the stashed working content into BOTH the index and the worktree. Every wt rollback row (FIXERR-wt, FIXERR-wt-MIXED, FIXTIMEOUT-wt, FIXERR-R2-wt, MULTI-FIXERR-wt) therefore pins: the file bytes equal the pre-fix worktree bytes; the index entry for each restored file equals its worktree content (`git diff -- <file>` is empty); and stderr contains exactly "Stash pop conflicted; falling back to per-file restore." and "Force-restored". The "Restored working tree from stash checkpoint." line is unreachable and is never pinned. These rows list delta 40 (T119), which makes rollback preserve the staged/unstaged split. FIXERR-wt-MIXED is the row T119 flips to assert both `git diff --cached` and `git diff` are unchanged. Verified by `node --test test/parity/loop-working-tree.test.mjs test/parity/loop-branch.test.mjs test/parity/loop-common.test.mjs`.
R2 Delta 40 tags. FIXERR-wt, FIXERR-wt-MIXED, FIXTIMEOUT-wt, FIXERR-R2-wt and MULTI-FIXERR-wt list 40 (AP3 fields for 40: ["stderr","gitState"]). Branch rows never list 40. Verified by `node --test test/parity/loop-working-tree.test.mjs test/parity/loop-branch.test.mjs test/parity/loop-common.test.mjs`.
R3 Timing and stash position. Before delta 2, the FIXTIMEOUT rows pass `--timeout 1` (the fixer budget is 2x, so 2 s) and the FIFO is never released. The seeded user stash sits at stash@{1} while a checkpoint exists and at stash@{0} after the run; rows assert the position at the end of the run. The ticket's "sleep is used only by LOOP-FIXTIMEOUT" is superseded: no T54 row uses sleep. Verified by `node --test test/parity/loop-working-tree.test.mjs test/parity/loop-branch.test.mjs test/parity/loop-common.test.mjs`.
R4 Vacuousness fixes. (AC3) Every --json row must validate its full stdout through `validateLoopEvents(run)`, a local wrapper defined in test/parity/loop-common.test.mjs and imported by the other loop files. It calls T51's assertValidEvents (schema-lite.mjs stays untouched; it is railed) and records the current row id in a module-level Set. An after() hook in each loop file fails any --json row whose id is not in the Set. Negative control: a --json row without validation fails. (AC6) A lint in loop-common.test.mjs fails on stash-name or epoch literals in loop-*.test.mjs sources (/adversarial-review-loop-\d{10,}/ and 13-digit numbers) and on git-state assertions that bypass gitState(). Negative control: a fixture string. (AP2) A source scan asserts the NOPROG-wt row asserts stashRef and the NOPROG-br row asserts originalHead. Negative control: an injected row without those assertions. (AP4) A source scan asserts every wt rollback row asserts the gitignored file's bytes. Negative control: an injected row omitting it. All are in loop-common.test.mjs. Verified by `node --test test/parity/loop-working-tree.test.mjs test/parity/loop-branch.test.mjs test/parity/loop-common.test.mjs`.
