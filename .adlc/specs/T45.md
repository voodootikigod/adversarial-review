# Spec T45: Add GitHub Copilot CLI (`copilot`) as an explicit review provider

## Context & Problem
`adversarial-review` supports five local CLI agents (`codex`, `claude`, `agy`, `agent`/`cursor-agent`). GitHub Copilot CLI is now a capable headless agent with a real read-only mode, and is installed on many developer machines that have no `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` — for those users there is currently no local reviewer available at all.

Empirical findings from Copilot CLI 1.0.77 (verified on macOS before writing this spec):

- `copilot -p '<text>' --mode plan -s --no-color --log-level none` runs non-interactively, exits 0, and emits **only** the agent response on stdout. A probe prompt returned the bare string `{"ok":true}`.
- `--mode plan` is a genuine read-only gate. A prompt instructing the agent to create `pwned-cp.txt` produced a refusal ("Per plan mode rules, I outline the approach but don't execute file changes") and **no file was created**.
- **The prompt is argv-only.** `-p -` is NOT a stdin sentinel: Copilot reads the literal `-` as the prompt and replies "I notice your message is empty." This is the same calling convention as `agy` (see `cliRequiresArgvPrompt` in `src/llm.js:324`), not the `claude`/`codex` stdin convention.

## Proposed Solution
Add `copilot` as an **explicit-only, family-less** local CLI provider on the review path.

**Diversity treatment.** Copilot CLI is a multi-provider router (`--model` selects Claude, GPT, or Gemini models). Per the existing precedent for `cursor`/`agent` at `src/llm.js:1051-1054` — "counting it as an independent family would fake diversity" — `copilot` MUST NOT be added to `TOKEN_FAMILY`. `familyKey()` at `src/llm.js:1207` already falls back to the token itself for unrecognized tokens, so `copilot` becomes its own group with no change to the family tables. Deriving a family from the resolved `--model` is explicitly out of scope (tracked separately); a stale model-name map would silently mislabel an anthropic review as independent, which is the exact failure the family comment warns against.

**Auto-detection.** `copilot` MUST NOT be added to the auto-detection ladder (`src/llm.js:817-892`). It is reachable only via an explicit `--provider copilot` or a `--providers` token, matching its family-less status.

## Acceptance Criteria
- [ ] AC1: `cliRequiresArgvPrompt("copilot")` returns `true`. The predicate is generalized from the current `commandKind(cliCmd) === "agy"` equality to a set membership test covering `agy` and `copilot`, and `cliRequiresArgvPrompt("/opt/tools/copilot")` and `cliRequiresArgvPrompt("copilot.cmd")` also return `true` (path- and extension-normalized via `commandKind`). Verified in `test/llm.test.js`.
- [ ] AC2: `cliSandboxArgs("copilot")` returns `["--mode", "plan"]`, and returns `[]` when `allowUnsandboxedCli: true`. Verified in `test/llm.test.js`.
- [ ] AC3: `cliFallbackArgs("copilot", PROMPT)` returns an argv array that (a) contains `--mode plan`, `-s`, `--no-color`, and `--log-level none`, (b) contains `--model <m>` when a model is passed and no `--model` flag when it is not, and (c) ends with exactly `["-p", PROMPT]` — the prompt is the last element, immediately preceded by the flag that consumes it.
- [ ] AC4: `cliReviewArgs("copilot")` returns `[]` (no stdin path exists), so `callCliLLM` routes `copilot` through the argv branch guarded by `cliRequiresArgvPrompt`. Verified in `test/llm.test.js`.
- [ ] AC5: `CLI_ONLY_TOKENS` includes `"copilot"`, and `resolveProviderToken("copilot")` returns `{ id: "copilot", family: null, config }` when the CLI is reachable and `config: null` when it is not — it is never silently upgraded to an API provider. Verified in `test/llm.test.js`.
- [ ] AC6: `TOKEN_FAMILY` does NOT contain a `copilot` key; `familyForResolution("cli", "copilot")` returns `null`. A test asserts that `copilot` and a Big-3 family token resolve to different `familyKey()` groups.
- [ ] AC7: `--provider copilot` resolves to `{ provider: "cli", cliCmd: "copilot" }`, and the auto-detection ladder never selects `copilot` when no explicit provider is given (asserted with every API key absent and `copilot` present on PATH).
- [ ] AC8: On Windows, a `copilot` installed as a `.cmd` shim is rejected: `cliUsableForReview("copilot", { platform: "win32" })` returns `false` for a batch shim, and `cliReachableForReview("copilot")` is correspondingly `false`, so no selection path picks a provider the spawn site would refuse. Verified in `test/windows-spawn.test.mjs`.
- [ ] AC9: `describeUnknownFlagRejection("copilot", stderr)` returns a clean `provider "copilot" rejected flag "--<name>"` string for Copilot's actual commander.js rejection text. The literal stderr Copilot emits for an unknown option MUST be captured empirically and used as the test fixture; if it is quote-wrapped (e.g. `error: unknown option '--foo'`), the existing regex at `src/llm.js:399` must be extended to strip surrounding quotes rather than reporting `--'--foo'`.
- [ ] AC10: An integration test asserts the full argv built for a review invocation is accepted by the real CLI when `copilot` is on PATH, and is skipped cleanly when it is not (follow the existing skip pattern in `test/cli-multiprovider.test.js`).
- [ ] AC11: `README.md` and `skills/adversarial-review/SKILL.md` document `--provider copilot`, state that it is explicit-only and does not count toward cross-family diversity, and note the argv-prompt/Windows-shim limitation. Verified via `grep -i "copilot" README.md skills/adversarial-review/SKILL.md`.
- [ ] AC12: `npm test` passes.
