# Spec T47: Collapse Vercel AI Gateway model pins to a single source of truth and detect catalog drift

## Context & Problem
Vercel AI Gateway is already a fully supported provider (`--provider vercel` / `gateway`, `AI_GATEWAY_API_KEY` or `VERCEL_OIDC_TOKEN`). Nothing needs adding. But its default model pins have a maintainability defect that silently degrades review quality.

**The same model strings are hardcoded in six places across four sites in `src/llm.js`:**

```
822:  gatewayPreferModel = "openai/gpt-5";
854:  gatewayPreferModel = "anthropic/claude-sonnet-4.6";
993:  model = gatewayPreferModel || cfgModel || "anthropic/claude-sonnet-4.6";
1070: openai:    "openai/gpt-5",
1071: anthropic: "anthropic/claude-sonnet-4.6",
1072: gemini:    "google/gemini-2.5-pro"
```

`GATEWAY_FAMILY_MODELS` (1069-1073) reads like the source of truth but is not — lines 822, 854, and 993 each hardcode the same strings independently. Changing the map alone does not change auto-detection behavior.

**The pins have drifted.** Verified against `GET https://ai-gateway.vercel.sh/v1/models` (312 models; the endpoint requires **no authentication**):

| Family | Pinned | Context | Newest suitable | Context | Status |
| --- | --- | --- | --- | --- | --- |
| openai | `openai/gpt-5` | 400,000 | `openai/gpt-5.6-sol` | 1,050,000 | stale — 5.1 through 5.6 all shipped |
| anthropic | `anthropic/claude-sonnet-4.6` | 1,000,000 | `anthropic/claude-sonnet-5` | 1,000,000 | stale — a full major generation |
| gemini | `google/gemini-2.5-pro` | 1,048,576 | — | — | **keep** — see below |

All three pins still resolve, so nothing is currently broken. The harm is quiet: an older reviewer catches fewer bugs and nothing surfaces that fact.

**Gemini deliberately does not move.** The catalog contains no stable 3.x *pro* text model. The 3.x line is `gemini-3-flash`, `gemini-3.5-flash`, `gemini-3.6-flash`, `gemini-3.1-flash-lite`, image variants, and exactly one pro: `google/gemini-3.1-pro-preview`. Moving off `gemini-2.5-pro` would mean either dropping to a weaker `flash` tier or adopting a preview model. The current pin is the correct conservative choice and must stay, with the reasoning recorded in a code comment so the next reader does not "fix" it.

**Tier is preserved on the pins that do move.** `gpt-5` → `gpt-5.6-sol` and `claude-sonnet-4.6` → `claude-sonnet-5` each stay in their existing tier rather than jumping to a `-pro` / `-opus` tier, so review cost and latency characteristics are unchanged. The openai move also raises the context window 2.6x (400k → 1.05M), which directly benefits large-diff review.

## Proposed Solution
1. Make `GATEWAY_FAMILY_MODELS` the only place a gateway model id is written. Lines 822, 854, and 993 read from it.
2. Move the openai and anthropic pins forward; leave gemini pinned with a comment explaining why.
3. Add a catalog drift test against the unauthenticated models endpoint that fails when a pin has been **removed** and reports — without failing — when a newer same-family, same-tier model exists.

**The drift test must never make `npm test` depend on the network.** It fetches with a short timeout and **skips** on any network error, non-200, or unparseable body. A missing pin is a real failure; an unreachable Vercel is not.

## Acceptance Criteria
- [x] AC1: `GATEWAY_FAMILY_MODELS` is the single source of truth. No gateway model id literal (`openai/…`, `anthropic/…`, `google/…`) appears anywhere else in `src/`. Enforced by a test in `test/gateway-model-drift.test.mjs` that greps `src/llm.js` and asserts zero matches outside the map definition.
- [x] AC2: The auto-detection ladder assignments at `src/llm.js:822` and `:854` read `GATEWAY_FAMILY_MODELS.openai` and `GATEWAY_FAMILY_MODELS.anthropic` rather than string literals. Verified in `test/llm.test.js` by asserting the resolved `gatewayPreferModel` equals the map value for each ladder branch.
- [x] AC3: The fallback default at `src/llm.js:993` reads `GATEWAY_FAMILY_MODELS.anthropic` rather than a literal. Verified in `test/llm-config.test.mjs`.
- [x] AC4: Pins are `openai: "openai/gpt-5.6-sol"`, `anthropic: "anthropic/claude-sonnet-5"`, `gemini: "google/gemini-2.5-pro"`. A code comment above the gemini entry records that no stable 3.x pro text model exists and that `gemini-3.1-pro-preview` was rejected as a preview. Verified in `test/llm.test.js`.
- [x] AC5: Model precedence is unchanged: an explicit `--model` still beats `gatewayPreferModel`, which beats the configured model, which beats the map default. Verified in `test/llm-config.test.mjs` with a case for each rung.
- [x] AC6: A drift test in `test/gateway-model-drift.test.mjs` fetches `https://ai-gateway.vercel.sh/v1/models` with no auth header and asserts every value in `GATEWAY_FAMILY_MODELS` is present in the returned `data[].id` set. A removed pin fails the test.
- [x] AC7: The drift test **skips rather than fails** on network error, non-200 status, timeout, or unparseable JSON, and uses a timeout of 15s or less. Verified by injecting a stubbed fetch that throws, one that returns 503, and one that returns malformed JSON — each case must skip, not fail. `npm test` MUST pass with networking disabled.
- [x] AC8: The drift test emits a non-failing diagnostic listing newer same-family models present in the catalog but not pinned, so drift is visible without blocking a build. Verified in `test/gateway-model-drift.test.mjs` with a stubbed catalog containing a newer id.
- [x] AC9: The **gateway** model references in `README.md` (line 251 default, and the `provider/model` examples at line 260) reflect the new pins. The **native-API** defaults at `README.md:247-249` (`claude-sonnet-4-6`, `gemini-2.5-pro`, `gpt-5`) and the config example at `README.md:287` are NOT gateway pins and MUST NOT be touched by this ticket. Verification MUST use fixed-string greps (`grep -F`): an unescaped `grep "claude-sonnet-4.6"` also matches the native form `claude-sonnet-4-6` at line 247, because `.` is a wildcard. Verified by: `grep -cF 'anthropic/claude-sonnet-4.6' README.md` returns 0; `grep -cF 'anthropic/claude-sonnet-5' README.md` returns ≥1; `grep -cF 'openai/gpt-5.6-sol' README.md` returns ≥1; `grep -cF 'google/gemini-2.5-pro' README.md` returns ≥1 (unchanged); and `grep -cF 'claude-sonnet-4-6' README.md` still returns 1 (the native default, deliberately preserved).
- [x] AC10: `npm test` passes, both with and without network access.

## Scope & Target Files
- `src/llm.js`
- `test/llm.test.js`
- `test/llm-config.test.mjs`
- `test/gateway-model-drift.test.mjs` (new)
- `README.md`

## Out of Scope
- Adding Vercel AI Gateway as a provider — it already exists and is fully wired.
- Changing the gateway's status as a transport rather than a diversity family (`src/llm.js:1055`). That design is correct and stays.
- Automatically resolving pins at runtime from the catalog. Runtime model selection must stay deterministic and offline-capable; drift detection belongs in tests, not in the review path.
- Moving the gemini pin.

## Risks
- **Network-dependent test.** A drift test that fails offline would make the suite unrunnable on a plane or in a sandboxed CI runner. AC7 is the mitigation and is tested with three distinct failure injections.
- **Behavior change from new pins.** Both replacement models are `type: language` with context windows greater than or equal to the models they replace, so no large-diff path regresses. Confirmed against the live catalog.

## Verification Methods
- `test/gateway-model-drift.test.mjs` for single-source-of-truth enforcement, catalog presence, skip-on-failure behavior, and the newer-model diagnostic.
- `test/llm.test.js` and `test/llm-config.test.mjs` for ladder assignment, fallback default, and precedence.
- Fixed-string greps per AC9 (`grep -cF`, never an unescaped pattern — `.` would also match the native `claude-sonnet-4-6`).
- `npm test` full suite green, verified both online and with networking disabled.
