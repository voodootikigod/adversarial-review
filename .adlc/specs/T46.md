# Spec T46: Add `opencode` (with the `opencode-go` provider) as an explicit review provider

## Context & Problem
`opencode` is a widely installed local agent that authenticates a set of model providers the review tool cannot otherwise reach. In particular its `opencode-go` provider routes to models outside the three frontier labs — `grok-4.5`, `kimi-k3`, `kimi-k2.7-code`, `qwen3.7-max`, `glm-5.2`, `deepseek-v4-pro`, `minimax-m3`, `mimo-v2.5-pro` — which are genuinely independent critics of code written by a Big-3 model.

Empirical findings from opencode 1.18.11 (verified on macOS before writing this spec):

- `opencode run` reads the prompt from **stdin** with no sentinel argument, and exits **1** on failure (verified against a credit-exhaustion error). This is the cleanest calling convention of any supported CLI.
- Agent response goes to **stdout**; the session banner (`> advreview · kimi-k2.7-code`) goes to **stderr**. A probe returned stdout containing exactly `{"ok":true}`.
- **There is no read-only flag.** `--agent plan` does NOT fail closed: opencode prints `! agent "plan" is a subagent, not a primary agent. Falling back to default agent` and proceeds under the user's configured default primary agent. On the machine this spec was written on, that agent carries `{"permission": "*", "action": "allow"}` — full write and bash access, applied to a prompt derived from an untrusted diff.
- Read-only **can** be enforced by generating a config that declares a primary agent with tools and permissions denied, and pointing `OPENCODE_CONFIG` at it. Verified: with such a config, a prompt instructing the agent to create `pwned-oc.txt` produced "I don't have a `write` or `bash` tool available in this environment" and **no file was created**.
- **An enabled tool whose permission is unset hangs the run indefinitely.** A config that disabled `write`/`edit`/`patch`/`bash` but left `read`/`grep`/`glob` enabled with no explicit permission caused `opencode run` to block forever on an interactive permission prompt with no output and no error — two runs were killed by an external timeout at 400s and 500s. There is no headless auto-deny. The generated config MUST set an explicit catch-all (`"permission": { "*": "deny" }`) plus an explicit `"allow"` for every tool it enables.
- **Disabling all tools is also wrong.** With every tool disabled the model returned quickly but stopped mid-turn without answering ("I'll audit the ticket... Reading the full spec...") because it had planned tool calls it could not make. A useful reviewer needs `read`/`grep`/`glob`/`list`.
- The config shape verified working end-to-end is: `tools: { write: false, edit: false, patch: false, bash: false, task: false, read: true, grep: true, glob: true, list: true }` with `permission: { "*": "deny", read: "allow", grep: "allow", glob: "allow", list: "allow" }`. Under it, `opencode-go/grok-4.5` read the repository and returned a well-formed answer, exit 0.
- **stdout interleaves tool-call narration with the answer.** Under `--format default` the payload arrived as prose fragments ("Reading the full spec and key implementation touchpoints next.") concatenated directly before the JSON object, with no delimiter.
- `src/exec-watchdog.js:159` hardcodes `env: sanitizedSpawnEnv()` with no override hook, so injecting `OPENCODE_CONFIG` requires a change to the spawn layer.

## Proposed Solution
Add `opencode` as an **explicit-only, family-less** local CLI provider on the review path, sandboxed by a generated read-only config injected via `OPENCODE_CONFIG`.

**Diversity treatment.** Identical to T45's rationale. `opencode` is a multi-provider router, and even `opencode-go` is not family-pure (it includes `gpt-5.6-luna`, an OpenAI-family model). It MUST NOT be added to `TOKEN_FAMILY`; `familyKey()` at `src/llm.js:1207` gives it its own group for free.

**Sandbox.** Follow the `callCodexCli` privateDir precedent at `src/llm.js:474-486` exactly: `fs.mkdtempSync` in `os.tmpdir()`, config written with `mode: 0o600` and `flag: "wx"`, whole directory removed in a `finally`. The config declares one primary agent with `write`, `edit`, `patch`, and `bash` tools disabled and `edit`/`bash`/`webfetch` permissions denied. The temp directory MUST be outside the worktree.

**Env injection.** `spawnWithWatchdog` gains a narrow `envOverrides` option: a plain object of string keys applied **on top of** the result of `sanitizedSpawnEnv()`, never replacing it. PATH sanitization and every other trust-root guarantee are preserved. The sole caller passes one fixed key (`OPENCODE_CONFIG`) whose value is a path this process generated; no value derived from the diff or from repository content may reach it.

## Acceptance Criteria
- [ ] AC1: `spawnWithWatchdog` accepts an `envOverrides` object and spawns the child with `{ ...sanitizedSpawnEnv(), ...envOverrides }`. A test asserts that (a) the overrides are present in the child environment, (b) the sanitized `PATH` is unchanged by an override attempting to set `PATH`, and (c) omitting `envOverrides` produces byte-identical behavior to today.
- [ ] AC2: A generated opencode config declares exactly one primary agent with `tools: { write: false, edit: false, patch: false, bash: false, task: false, read: true, grep: true, glob: true, list: true }` and `permission: { "*": "deny", read: "allow", grep: "allow", glob: "allow", list: "allow" }`. The file is created in a `fs.mkdtempSync` directory with `mode: 0o600` and `flag: "wx"`, and the directory is removed in a `finally` block even when the CLI throws. Verified in `test/llm.test.js`.
- [ ] AC2b: The generated config contains a catch-all `"*": "deny"` permission, and every tool set to `true` in `tools` has a corresponding explicit `"allow"` entry in `permission`. A test in `test/llm.test.js` asserts this invariant structurally — an enabled tool with no explicit permission is the documented indefinite-hang condition and must be impossible to emit.
- [ ] AC3: The generated config path is outside the git worktree. A test asserts the path is not inside `process.cwd()`.
- [ ] AC4: **Determine empirically whether `OPENCODE_CONFIG` replaces or merges the user's own config**, and record the finding in a code comment. If it replaces, an explicit `-m <provider/model>` is mandatory on every invocation (the user's default model is otherwise lost) and the implementation MUST always pass one.
- [ ] AC5: A default model constant is defined for `opencode` and is overridable by `--model`. When opencode reports the model is unavailable or unauthenticated, the error surfaced to the user names the model and states that `opencode auth list` shows which providers are authenticated — not an opaque exit-1.
- [ ] AC6: The prompt is delivered over **stdin** (no sentinel argument), so `cliRequiresArgvPrompt("opencode")` returns `false` and the argv-size guard does not apply. A test in `test/llm.test.js` asserts the built argv contains no element equal to the prompt.
- [ ] AC7: The invocation always passes `--agent <generated-agent-name>`. A test asserts that a run whose `--agent` is missing or names a subagent is treated as a failure rather than allowed to fall back to the user's default agent — the silent-fallback behavior documented above must not be reachable.
- [ ] AC8: Only stdout is parsed for the review payload; the stderr banner is excluded. A test in `test/llm.test.js` feeds a captured stdout/stderr pair and asserts the banner text never reaches the JSON extractor.
- [ ] AC8b: The extractor tolerates tool-call narration concatenated ahead of the JSON payload on stdout, with no delimiter (see the captured sample in the findings above). Evaluate `--format json` (raw JSON events) as a cleaner alternative and record the choice in a code comment; whichever is chosen, a test in `test/llm.test.js` uses a real captured stdout sample as its fixture.
- [ ] AC9: `CLI_ONLY_TOKENS` includes `"opencode"`; `resolveProviderToken("opencode")` returns `family: null` and is never upgraded to an API provider. `TOKEN_FAMILY` does NOT contain an `opencode` or `opencode-go` key.
- [ ] AC10: `--provider opencode` resolves to `{ provider: "cli", cliCmd: "opencode" }`, and the auto-detection ladder never selects `opencode` when no explicit provider is given.
- [ ] AC11: An end-to-end test in `test/cli-multiprovider.test.js` asserts read-only enforcement holds: with the generated config, a prompt instructing the agent to write a file into a temp workspace leaves that file absent. PATH-gated — skipped cleanly when `opencode` is not installed.
- [ ] AC12: `README.md` and `skills/adversarial-review/SKILL.md` document `--provider opencode`, the `opencode-go` model set, explicit-only/family-less status, and the generated-config sandbox. Verified via `grep -i "opencode" README.md skills/adversarial-review/SKILL.md`.
- [ ] AC13: `npm test` passes, including the existing `test/exec-watchdog.test.js` and `test/spawn-safe.test.js` suites unmodified in intent.

- Exposing `opencode-go` as a selectable provider token distinct from `opencode`; model selection is via `--model opencode-go/<name>`.

## Risks
- **Spawn-layer change.** `envOverrides` touches security-sensitive code. Mitigation: overrides apply after sanitization and cannot replace `PATH`; the only caller passes a fixed key with a self-generated value. AC1 tests the negative case directly.
- **Config semantics unknown.** AC4 exists to resolve the replace-vs-merge question before the implementation depends on either answer.
- **Silent indefinite hang.** A misconfigured permission set does not error — it blocks forever with no output. The existing watchdog timeout is the only backstop, so a config bug would surface to users as an opaque timeout rather than a config error. AC2b makes the bad shape structurally unemittable; that test is the primary defense, not the timeout.

## Verification Methods

- Unit tests in `test/llm.test.js` for config generation, argv construction, stdout-only parsing, token resolution, and family exclusion.
- PATH-gated end-to-end read-only enforcement test.
