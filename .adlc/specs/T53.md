# Spec T53: Parity rows for precedence, MULTI stage order, CLI errors and fallback lifecycle (ROADMAP step 0)

Status: P1 draft (2026-10-07). The ticket body below is authoritative. The sections above it pin parallax resolutions and, after the premortem, the premortem decisions; where they are more specific, they win. The T50 spec (.adlc/specs/T50.md) is binding for every helper and rule used here.

## Resolved implementation decisions (parallax round 1)

1. **Mutant staleness.** T50 AP9 governs. A refactor ticket may not edit a NEG-* mutant's `find`; a stale mutant is re-targeted in a separate approved commit before the refactor merges.
2. **NEG rows** use T50's mutant pattern (AC6/AP9): `withMutant([...], async (cliEntry) => ...)`, which runs the target row's assertion body against the mutated copy and requires it to fail. Every mutant's load sentinel must fire.
3. **Raw-token leak sweep.** Every secret row calls a local helper, `assertNoTokenLeak(run, token, { allowStubBody })`. It asserts the raw token is absent from the capture's `requests[].body`, `prompts[].argv`, `prompts[].stdin`, stdout and stderr, and from the ledger file bytes when a ledger is used. Rows run with `--allow-secrets` (PREC-GROUNDING-*) pass `allowStubBody: true`, because the payload is meant to reach the provider there. Negative control in precedence.test.mjs: the helper throws on a synthetic capture that contains the token in stdout.
4. **Fixture tokens** are built at runtime by concatenation (for example `'AKIA' + 'PARITYFIXTURE001'` and `'sk-' + 'paritytoken'.repeat(4)`), so the repository never contains a secret-shaped literal. A positive sibling proves each token triggers the 2.11.1 scanner: PREC-SECRET-NOCALL for AKIA, and PREC-PROMPTONLY-SECRET's warning. This proves the empty-scope row passes because of stage order, not because the token goes undetected.
5. **Grounding mutant.** Add NEG-PREC-GROUNDING: a mutant that feeds grounding the scrubbed evidence must make PREC-GROUNDING-UNREDACTED fail (the grounding note appears). No new non-NEG rows are added (a multi-provider ledger row was considered and rejected as out of scope).
6. **Lifecycle assertions.** LIFECYCLE-CACHE-WRITE checks `cache.default.provider === 'anthropic'` (the shape follows the code). LIFECYCLE-NONSTALE-NO-FALLBACK asserts the cache file is unchanged by deep equality of the parsed JSON before and after. The seed is built with `withResolution` from src/config-store.js or copied from CACHE-WRITE's output, never hand-written.
7. **Counts and ordering.** Exact invocation counts only where retry or no-call is the behavior under test: TIMEOUT 1, UNKNOWN-FLAG 1, GENERIC 2, SECRET-NOCALL and EMPTY 0, LIFECYCLE stub/codex counts, ARGV-TOO-LARGE as pinned. Single-mode verify order is the classification sequence [review, verify, verify] from ctx.records. MULTI rows never assert ordering across providers (delta 12 makes it concurrent), only per-finding outcomes (corroborated_by, the chosen evidence).

Agreed by all readings and adopted as stated in the ticket: stderr is checked by substring only (no assertStderrExact, so no tag 36), JSON through assertValidOutput plus targeted field reads, the scan-adjacent rows grouped in one describe block so delta 17 edits one place, no `--focus` use, and every row with a fresh configPath and a temp HOME (the real-config mtime check is a read-only backstop).

## Premortem decisions (interrogation round 2, 2026-10-07; binding, extend the ticket's ACs)

AP1 Stage-order invariant for pair 1. In 3.0.0 the empty-scope exit still precedes the secret check: ROADMAP R1 places the empty exit "before any provider or quorum logic", and delta 17's full-prompt scan runs after provider resolution (P0 decision Q5). PREC-EMPTY-SECRET-* rows therefore stay strict through delta 17, and no ticket may remove their "no Possible secret" or "no Refusing to send" exclusions. Verified by a guard test in precedence.test.mjs that reads test/parity/rows/precedence.json and fails if any PREC-EMPTY-SECRET-* entry lists 17. Negative control: an injected manifest entry listing 17 fails the guard.

AP2 Leak sweep reach. assertNoTokenLeak(run, token, { allowStubBody }) searches, after each secret row, every file written under the run's temp HOME, repo dir, mocksDir and TMPDIR (a recursive walk excluding .git/objects); the mocks' recorded child env (`prompts[].env` values); the capture's argv, stdin, stdout, stderr and request bodies; and the ledger file. It searches each in four forms: raw, JSON-escaped, base64 and URL-encoded. With allowStubBody it still asserts the token appears ONLY in stub request bodies. Verified in precedence.test.mjs: one negative control per surface and form (a synthetic run containing the token in that place makes the helper throw naming the surface and form), and a positive case where a clean run passes.

AP3 One detection-proof row per fixture token. Rows TOKEN-PROOF-AKIA and TOKEN-PROOF-SK each run a working-tree diff containing the runtime-built token with --prompt-only. Each asserts stderr contains "Possible secret" naming that token's pattern, and asserts the exact masked form 2.11.1 produces for that token (captured from a run, pinned as a constant, asserted as present). Tokens are realistic-entropy strings built at runtime. futureDeltas [9]. Verified by `node --test test/parity/precedence.test.mjs`. Negative control: the same row with the token's middle character replaced by a non-matching character makes the 'Possible secret' assertion fail.

AP4 Review/verify order by mock-side sequencing. The claude mock answers call 1 with a review-shaped answer (findings) and later calls with verify-shaped answers (refuted/confirmed). PREC-REVIEW-BEFORE-VERIFY asserts the expected outcome (both findings verified, the result as pinned), so verify running first would receive a review-shaped answer and the row fails. isReviewPrompt/isVerifyPrompt are not used for ordering. Add NEG-PREC-VERIFY-FIRST: a mutant that runs verification before review makes the row fail with the named signature (AP10). Verified by `node --test test/parity/precedence.test.mjs`.

AP5 Grounding assertions. PREC-GROUNDING-UNREDACTED asserts that the finding's `confidence` in the stdout JSON equals the reviewer's value; PREC-GROUNDING-CONTROL asserts it equals half of it. Both rows also check the note through ONE shared constant `GROUNDING_NOTE` (value captured from 2.11.1), absent and present respectively. NEG-PREC-GROUNDING stays mandatory. Verified by `node --test test/parity/precedence.test.mjs`.

AP6 Ledger pins an exact masked title. PREC-LEDGER-EQUALS-PRINTED asserts that the ledger `desc` and the printed finding `title` each EQUAL the literal masked title 2.11.1 produces for the fixture title (captured once, pinned as a constant), and that the raw token is absent (AP2). Verified by `node --test test/parity/precedence.test.mjs`. Negative control: a synthetic ledger whose desc equals the raw title fails.

AP7 MULTI representative is checked in both provider orders. STAGE-MULTI-GROUNDED-REPRESENTATIVE runs as two rows, -GROUNDED-FIRST and -GROUNDED-SECOND (provider order in `--providers` swapped); both must emit the grounded provider's evidence. corroborated_by is always compared with exact deepEqual, never `includes`. Verified by `node --test test/parity/stage-order-multi.test.mjs`.

AP8 CLI error rows split message from count. Each CLIERR case becomes two rows: CLIERR-<X>-MSG (exit code plus the pinned message substring) and CLIERR-<X>-COUNT (exit code plus the exact invocation count). The C5 classifier's landing may edit -MSG rows only; -COUNT rows carry no C5-related tag, so a count or exit change needs a separate approved rail commit. Verified by a guard test in cli-errors.test.mjs that asserts no -COUNT manifest entry shares a tag with the C5 classifier landing (recorded in the manifest as the `c5Editable: false` marker) and that every CLIERR case has both rows. Negative control: an injected -COUNT entry marked editable fails the guard.

AP9 Deterministic argv-too-large. CLIERR-ARGV-TOO-LARGE-* inline a ~4 MiB diff (with --max-bytes raised to inline it), far above Linux's 128 KiB per-argument limit and macOS's ~1 MiB total, so copilot is never spawned on any CI platform. No platform skip. Verified by `node --test test/parity/cli-errors.test.mjs` on the Linux and macOS runners; the -COUNT row asserts 0 copilot invocations.

AP10 NEG mutants prove a named failure, and that the mutated lines ran. Each NEG row asserts the specific failure its target row names (for example exit 1 with "Refusing to send", or a wrong corroborated_by value), not merely that the row failed. Each mutant's replacement code writes `PARITY-MUTANT-RAN:<NEG id>` to stderr from inside the mutated block (process.stderr.write needs no import), and the NEG row asserts that line is present. A crash, or a mutant whose block never executed, therefore cannot count as proof. This works alongside T50's file-level load sentinel (AP9) and needs no T50 change. Verified by `node --test test/parity/*.test.mjs`. Negative control: a NEG row whose mutant targets an unexecuted branch fails because the RAN line is absent.

AP11 LIFECYCLE rows are converted under C4, never deleted. Per ROADMAP C4, after the cache is deleted "the stale-credential fallback applies to any auto-detected provider: on an auth/model failure it advances the table once". T80 and T83 must therefore CONVERT LIFECYCLE-STALE-CACHE-FALLBACK into a row pinning re-detection on a 401 without a cache, not delete it. One LIFECYCLE row seeds its cache from a COMMITTED 2.11.1-format fixture file, test/parity/fixtures/config-2.11.1.json, rather than from the current writer, so a shape change in config-store cannot silently move the seed. Verified by `node --test test/parity/fallback-lifecycle.test.mjs`. A guard asserts the fixture file exists and parses.

## Round 3 resolutions (re-reads and vacuousness audit, 2026-10-07; binding, override AP text where they conflict)

R1 AP5 correction (verified against 2.11.1). The JSON `confidence` is never halved; assessFindings halves only `effectiveConfidence`, which decides gating. The grounding rows therefore assert through the GATING OUTCOME, an output-observable consequence: the reviewer's finding has confidence 0.9 and severity at or above failOn. PREC-GROUNDING-UNREDACTED (grounded) -> exit 2, verdict needs-attention, and GROUNDING_NOTE ('confidence halved for gating') absent. PREC-GROUNDING-CONTROL (ungrounded) -> exit 0, verdict approve (0.45 < 0.5), and GROUNDING_NOTE present. Both assert that the JSON confidence equals 0.9 unchanged. NEG-PREC-GROUNDING (grounding fed scrubbed evidence) must make UNREDACTED exit 0 and show the note, plus the RAN marker.
R2 AP4 mutant correction. A verify-first mutant over an empty finding set makes no verify call, so it proves nothing. NEG-PREC-VERIFY-FIRST mutates runOneReview to call verifyFindings on a one-finding result built inside the mutant BEFORE runReview. The sequenced mock's review-shaped call-1 answer then goes to verify and the review receives a verify-shaped answer. The named failure is exit 1 (parse/schema failure of the review), plus the RAN marker. PREC-REVIEW-BEFORE-VERIFY asserts exactly 3 claude invocations and the pinned outcome, without prompt classification.
R3 AP2 mechanics. The env surface is `ctx.records(name)[i].env` (T50 decision 4), not a capture field; secret rows set recordEnv for the env names the CLI passes. The file walk compares a (path, sha256) snapshot taken before the run with one taken after, and sweeps only NEW or CHANGED files, so planted fixture inputs are excluded. The whole `.git` directory is excluded (COMMIT_EDITMSG and logs hold the planted commit message). The sweep is required on rows that reach or would reach a provider (PREC-EMPTY-SECRET-*, PREC-SECRET-NOCALL-*, PREC-GROUNDING-*, PREC-LEDGER-*). PREC-PROMPTONLY-SECRET and TOKEN-PROOF-* run it with `allowStdout: true`, because --prompt-only prints the raw prompt by design. Base64 search covers all three byte alignments.
R4 AP3 controls and masked forms. Pinned masked forms (redact keeps the first 6 chars): AKIA token -> 'AKIAPA…(20 chars)' and sk- token -> 'sk-par…(<len> chars)' (U+2026), asserted from the scan line 'Possible secret in review payload: <pattern> (<masked>)'. Negative controls: for sk-, replace the character at index 13 with '.' (it leaves no 20-char run); for AKIA, lowercase one tail character.
R5 AP8 split by FILE, not a manifest marker (no change to T50's manifest schema). -COUNT rows (exit code plus exact invocation count) live in test/parity/cli-errors-counts.test.mjs with manifest rows/cli-errors-counts.json. -MSG rows (exit code plus message substring) stay in cli-errors.test.mjs. T108 (C5) must declare test/parity/cli-errors-counts.test.mjs and its manifest as RAILS, so `adlc rails-guard` mechanically blocks a C5 change from editing counts; a count change needs a separate approved ticket. There is no `c5Editable` key. Row ids are CLIERR-{TIMEOUT,ARGV-TOO-LARGE,UNKNOWN-FLAG,GENERIC}-{MSG,COUNT}. Each half inherits the parent's tags: TIMEOUT, UNKNOWN-FLAG and GENERIC get [1,9,31]; ARGV-TOO-LARGE gets [1]. NEG-CLIERR-UNKNOWN-FLAG targets -MSG. The ARGV row pins the message prefix 'Local CLI agent "copilot"', not byte counts.
R6 Tag lists for new and changed rows. PREC-EMPTY-SECRET-NL and -NL-FOE: [1]. PREC-EMPTY-SECRET-LOOP: [1,8,18,21] (AP1 removes 17). TOKEN-PROOF-AKIA and -SK: [9]. STAGE-MULTI-GROUNDED-REPRESENTATIVE-GROUNDED-FIRST and -GROUNDED-SECOND: [1,8,9,12,14,15,31] (the unsuffixed id is retired). NEG rows: [], with a roadmapRef naming the target row's section. No row lists 28, 34, 35, 36, 37 or 38.
R7 AP11 seeding and persistence. LIFECYCLE-STALE-CACHE-FALLBACK and LIFECYCLE-NONSTALE-NO-FALLBACK both seed by copying the committed test/parity/fixtures/config-2.11.1.json (captured from a CACHE-WRITE run with resolvedAt fixed) into the row's configPath. CACHE-WRITE asserts its output deep-equals the fixture except for resolvedAt. A source-scan test asserts that both seeded rows read that fixture and that neither calls the config-store writer. A manifest guard asserts LIFECYCLE-STALE-CACHE-FALLBACK stays present in rows/fallback-lifecycle.json (T80 may convert its body, never remove its id). Negative controls for both checks: an injected source without the fixture read, and an injected manifest without the id.
R8 Vacuousness fixes. (AC3) A manifest guard maps each of the six precedence pairs to exactly one row id (PREC-EMPTY-SECRET-LOOP is the loop half of pair 1) and fails on a missing or duplicate mapping; negative control: an injected duplicate. (AC5) A source-scan test requires assertValidOutput in every row() whose argv contains --json, and assertValidEvents in PREC-EMPTY-SECRET-LOOP; negative control: a fixture row with --json and no validation. (AC6) A captured 2.11.1 output fixture, test/parity/fixtures/messages-2.11.1.txt, is committed, and a test asserts every pinned message constant is a substring of it. (AC7) The real config path is resolved from the PARENT process env before any HOME override, and always checked: absent stays absent; present keeps the same mtime and sha256. Negative control: a row writing to that path makes the check fail.
