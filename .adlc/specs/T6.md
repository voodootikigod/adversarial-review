# T6 — `--input` artifact review mode (review specs/tickets/rail-sets, not just git diffs)

## Problem

The tool reviews only a git diff/branch: `bin/cli.js` validates scope to
`auto|working-tree|branch` and always calls `collectReviewContext` (git).
ADR-0008 maps adversarial review onto **P1** (design/spec review) and **P3**
(rail-set adequacy) — neither has a diff; they review a *document* or a declared
rail set. Without a first-class artifact input, P1/P3 review degrades to a
one-shot manual prompt outside the tool (no schema, no `--verify`, no
`--providers`, no ledger).

## Fix

Add `--input <file(s)>` as a review-target mode **alongside** `--scope`/`--base`.
Only the review **target** and the **charter** change; the schema, grounding,
`--verify`, `--providers`/`--quorum`, `--passes`, `--findings-ledger`, `--json`,
and `--prompt-only` machinery are reused unchanged.

### 1. `parseArgs` (src/utils.js)

`--input` is repeatable and comma-splittable; entries accumulate into
`args.input` (a `string[]`, default `null`). Empty entries error. Reject
`--input` combined with `--base`, `--scope working-tree|branch`, or `--loop`
(artifact mode has no diff / working tree to fix). Document in `HELP_TEXT`.

### 2. `collectArtifactContext(cwd, files, { maxBytes })` (NEW src/artifact-context.js)

Reads each named file (path resolved vs `cwd`; per-file cap
`MAX_INLINE_FILE_BYTES = 256 KB`; running total budget `maxBytes`; binary/oversize
skipped with an inline note; **missing/unreadable ⇒ throw**, fail closed). Returns
a shape compatible with the git context so the rest of the pipeline is untouched:

```
{ mode: "artifact", label, content, changedFiles: files, includeDiff: true,
  isEmpty, fileCount, diffBytes, collectionGuidance }
```

`includeDiff` is always `true` (the artifact IS the inlined content — there is no
git fallback to "inspect it yourself"). `isEmpty` is true only when every
successfully-read file had no content. `changedFiles = files` so the grounding
file-citation check treats a finding citing an input file as in-scope.

### 3. Artifact charter (NEW prompt-template-artifact.md)

An adversarial charter for a **design artifact** (spec / ticket / rail-set /
plan), distinct from the diff template's "map the change surface" / "each changed
file" framing. Attack surface: ambiguity, missing or untestable acceptance
criteria, unhandled failure modes, unaddressed trust-boundary/security concerns,
internal contradictions, unstated assumptions, missing rollback/migration/
observability. Same four placeholders
(`{{TARGET_LABEL}}`, `{{USER_FOCUS}}`, `{{REVIEW_COLLECTION_GUIDANCE}}`,
`{{REVIEW_INPUT}}`), same `structured_output_contract` + `grounding_rules` (quote
the artifact; cite artifact file + line; file-level finding ⇒ lines 0). The
output **schema (schema.json) is reused unchanged** (a frozen rail for this
ticket); design-level findings map onto the existing category enum, with `other`
for spec-specific gaps.

### 4. `buildArtifactPrompt(context, focus)` (src/review.js)

Loads `prompt-template-artifact.md` via the same placeholder substitution as
`buildPrompt`. `runReview`, `runMultiProviderReview`, `assessFindings`,
`mergeProviderResults`, `renderReport` are prompt-agnostic and reused as-is.

### 5. Wiring (bin/cli.js)

When `args.input` is set: skip git collection, build the artifact context and
`buildArtifactPrompt`, then run the EXISTING single-/multi-provider review +
grounding + `deriveVerdict` + render + exit path unchanged. `--prompt-only`
prints the artifact prompt. The secret scan still runs on the payload.

### 6. Skill bundle — NOT bundled (build-time revision)

Original plan was to bundle `prompt-template-artifact.md` into the skill and
extend the `test/skill-assets.test.js` drift guard. **Revised during P4:** the
skill does not wire `--input` yet, so a bundled copy would be an unused,
speculative asset, and `test/skill-assets.test.js` is a **frozen rail from T2** —
extending it would require a recorded rail bypass for no present benefit (YAGNI).
Decision: keep `prompt-template-artifact.md` **root-only**; do not bundle, do not
touch the frozen rail. Whoever wires `--input` into the skill later bundles it
then (with a justified bypass at that point).

## Out of scope

- `--loop` with `--input` (no working tree to fix — v1 rejects it).
- Changing `schema.json` (frozen rail) or the diff-based modes / their exit codes.
- Auto-detecting artifact vs diff (explicit `--input` only).
- Directory/glob inputs (explicit file paths only in v1).

## Acceptance criteria

- **AC1 (parse + mutual exclusion)** — verified by `node --test test/utils.test.js`:
  `parseArgs(["node","cli","--input","a.md","--input","b.md,c.md"]).input` equals
  `["a.md","b.md","c.md"]`; an empty `--input=` pushes an error; `--input` with
  each of `--base X`, `--scope branch`, `--scope working-tree`, `--loop` pushes a
  mutual-exclusion error; `--input` alone (scope defaulting to `auto`) does NOT
  error.

- **AC2 (collectArtifactContext, fail-closed)** — verified by `node --test test/artifact-context.test.js`:
  given two temp files with text, `content` inlines both bodies, `changedFiles`
  equals the input list, `includeDiff === true`, `isEmpty === false`. It **fails
  closed** (throws, never a silent empty context) when the target has no reviewable
  content: a nonexistent path, a binary file (NUL at byte 0), and an oversize
  target reached through a symlink (`statSync` follows the link so the cap sees the
  target) each throw; all-empty files throw `No reviewable content`. Revised twice
  under P5 adversarial review: (1) the original draft returned `isEmpty === true`
  for empty input, which `bin/cli.js` would exit `0 "approve"` — a fail-open;
  (2) the follow-up review flagged that a total byte budget could partially drop
  named files yet still approve. Final design has **no total byte budget and no
  silent skip** — `--max-bytes` is the per-file cap, a file over it is a hard error
  (raise `--max-bytes`), and an explicitly-named `--input` with nothing reviewable
  is exit 1, never a clean review.

- **AC3 (artifact charter, not the diff template)** — verified by `node --test test/artifact-context.test.js`:
  `buildArtifactPrompt` leaves **no** residual `{{...}}` placeholder, embeds the
  file content inside the prompt, contains artifact-review framing (e.g. the word
  `artifact`), and does **not** contain the diff template's tell `Map the change
  surface`. A snapshot that the artifact template ≠ the diff template.

- **AC4 (end-to-end review + exit code)** — verified by `node --test test/input-mode.test.mjs`:
  driving the real `bin/cli.js --input <file> --provider <mockcli> --json`, a mock
  reviewer returning a gating finding ⇒ stdout is schema-valid JSON and exit `2`;
  a mock returning `approve` ⇒ exit `0`.

- **AC5 (composes with --prompt-only)** — verified by `node --test test/input-mode.test.mjs`:
  `bin/cli.js --input <file> --prompt-only` exits `0`, makes no LLM call, and
  prints the artifact prompt containing both the artifact framing and the input
  file's content.

- **AC6 (full suite, no rail touched)** — verified by `npm test`: the whole suite
  exits 0, `prompt-template-artifact.md` lives at root only (not bundled), and the
  frozen rail `test/skill-assets.test.js` is unchanged (its two existing bundled
  assets still match).

- **AC7 (mutation-proven, one-time manual)** — verified by re-running the suite after each hand-applied mutation:
  (i) make `bin/cli.js` use `buildPrompt` (diff template) for `--input` ⇒ AC3/AC5
  fail; (ii) drop a `--input`×`--loop`/`--base`/`--scope` exclusion check ⇒ AC1
  fails; (iii) make a missing input file read as empty instead of throwing ⇒ AC2
  fails. Recorded in the manifest/PR, not shipped as extra tests.

## Risks / things a build agent should not do

- Do NOT edit `schema.json` (frozen rail) or add categories — design findings map
  onto the existing enum + `other`.
- Do NOT number the inlined artifact lines — the grounding evidence check does an
  exact substring match against `content`; injected line numbers would break it.
  The model estimates `line_start`/`line_end`; file-level gaps use line `0`.
- Do NOT restrict `--input` paths to inside the repo — the user names them
  explicitly (unlike git-derived untracked paths). Keep the binary/size guards.
- Keep the fix additive: the diff-based path (no `--input`) must be byte-for-byte
  behaviorally unchanged.

## P1 interrogation resolutions (premortem + parallax, self-answered)

- **R1 (schema reuse vs category fit)** — Reuse `schema.json` unchanged. A spec
  gap that is not obviously `security/auth/data-loss/correctness/...` uses `other`.
  Rationale: forking the schema would fork validation, rendering, merge, and the
  provider-facing sanitizer — huge blast radius for a naming nicety. The charter
  guides category selection instead.
- **R2 (grounding still applies)** — `assessFindings` is reused: `changedFiles =
  input files` grounds the file-citation check; `includeDiff = true` grounds the
  evidence-quote check against `content`. No artifact-specific grounding code.
- **R3 (fail closed on missing input)** — a named file that cannot be read
  THROWS (exit 1), never a silent empty context — mirrors git-context's
  fail-closed contract (an empty review must not read as "nothing to review /
  approve").
- **R4 (mutual exclusion, not silent override)** — `--input` + `--base`/`--scope
  working-tree|branch`/`--loop` is a hard parse error, not a silent win, so an
  ambiguous invocation can't quietly review the wrong target. `--scope auto`
  (the default) with `--input` is allowed (auto is not an explicit diff request).
- **R5 (prompt-only parity)** — `--input --prompt-only` prints the artifact
  prompt with no LLM call, so the P1/P3 manual-review path (feed to a model
  yourself) is first-class, matching diff-mode `--prompt-only`.
