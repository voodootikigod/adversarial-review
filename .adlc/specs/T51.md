Field resolutions:
- `fixerStderr` (WT fixer-error/fixer-timeout only): always present and always a string. spawnFixer (L674-790) resolves with `stderr` on all three paths: timeout `tailOf(...)` string (L770), close `tailOf(...)` string (L778), spawn `error` event `err.message` string (L784). A throw from spawnFixer (argv limit, unresolved fixer, missing bwrap/unshare) rejects before any event. So: string, may be empty, at most 2048 chars; never absent on those two exitReasons, never present on any other.
- `resumeHint`: `buildLoopSummary` defaults it to null and only sets the key `if (resumeHint)` (L182). extractResumeHint returns `{cli, id, command}` or null (src/resume-hint.js L64, L65). So the emitted key is absent or an object; null is NEVER emitted. Schema: object only, not nullable. `cli` is one of codex, agy, claude, agent (PATTERNS); pinned as an enum (Decision 3). Only reachable on fixer-error/fixer-timeout (L1347, L1729).
- `survivingCount`: integer >= 0 (literal 0 or `gatings.length`). `acceptedCount`: always the literal 0 (`const: 0`). `verdict`: "approve" iff exitReason "clean", else "needs-attention" (L174). `providers`: non-empty array of string (L951-953, L1158).
- `iteration`, `iterations`, `loopMax`, `findingCount`, `matchedIteration`: integers. loopMax >= 1 (parsePositiveInteger, src/utils.js L415); iteration >= 1; iterations >= 0.
- `scope`: enum ["working-tree", "branch"].
- `constraintMode`: from probeOsConstraint (L286-334) only "advisory" or "bwrap" (unshare/unshare-user detection still returns {mode:"advisory"} under --loop-unsafe; non-bwrap without --loop-unsafe throws before loop_start). Pinned as enum (Decision 2).
- `fixerCmd`: string, never null at 2.11.1 (null becomes legal only in step 3).
- `exitReason`: exactly the ticket's seven; "empty" and "clean" also come from the empty-scope paths.
- `review_result.result`: an object from the single-provider path (reviewRound result, NOT scrubbed, verdict NOT overwritten) or the multi-provider round (runProviderRound merged result, may carry `corroborated_by`); both satisfy schema.json. null only on the empty-scope clean path (iteration 1).

## Schema design (binding)
1. output-schema.json: byte-for-byte the same JSON value as schema.json, except that `$comment` may differ. AC1's structural comparison compares the full JSON value minus `$schema`/`$comment`/`$id`/`title`/`description` (deep-equal), which subsumes the property-set and bound checks.
2. loop-events-schema.json: root `{ "oneOf": [ ...one variant per type... ] }`, each variant `type: "object"`, `additionalProperties: false`, `required` including `type`, and `properties.type: { const: "<name>" }`. Per-scope variants per Decision 1 (two each for loop_start, fix, loop_end; one each for review, review_result, stash_created, fix_committed, loop_summary: eleven branches). Nullable fields use type arrays: loop_end.stashRef and fix.stashRef `["string","null"]`; review_result.result `oneOf: [<inlined review-result schema>, {type:"null"}]`.
3. Embedded review-result copy lives at `oneOf[<review_result>].properties.result.oneOf[0]`; the AC2 drift test locates it by finding the variant whose `type.const` is "review_result" (not by index) and deep-equals it to output-schema.json minus the root `$schema`/`$comment` keys.
4. schema-lite.mjs: `validate(schema, value) -> string[]` (path-prefixed messages; never throws on data), throws `Error("schema-lite: unsupported keyword <k> at <path>")` on any schema keyword outside the supported list. Keyword set is checked recursively on every subschema BEFORE validating, so an unsupported keyword in an untaken oneOf branch still throws. `integer` means `Number.isInteger(v)`; `number` excludes NaN/Infinity; `null` type matches only `null`; `object` excludes arrays and null. `const` and `enum` compare with deep equality for non-primitives. oneOf reports "matched 0 branches" / "matched N branches" with the branch errors.
5. assertValidOutput(doc) validates against output-schema.json; assertValidEvents(lines) accepts an array of strings (raw NDJSON lines) or of objects, JSON.parses strings, and throws one Error listing every line index with its errors (not just the first). Both read the schema files once via `fs.readFileSync` relative to the module (`new URL("../../../", import.meta.url)`), never from cwd.
6. The packaging assertion (AC7) is additive in test/packaging.test.js: it asserts `pkg.files` contains both names AND runs `npm pack --dry-run --json` (spawnSync, `npm` resolved from PATH, with `--ignore-scripts`) and asserts both paths appear in the listed `files`. If `npm` is not resolvable the pack half fails loudly (no skip).
7. Registry: T50's cross-manifest check rejects a .test.mjs without a manifest, so schemas.test.mjs ships with test/parity/rows/schemas.json and registers its real-output rows (SCHEMA-OUT-APPROVE, SCHEMA-OUT-FLAG, SCHEMA-LOOP-CONVERGE, SCHEMA-LOOP-BRANCH) and NEG-SCHEMA-LOOP via defineRows("schemas"). Pure unit tests (AC1-AC5, AP1-AP5) may be plain `test()` calls. futureDeltas follow T50 AP3 (a row is tagged with every taggable delta whose `fields` or envelope touch what the row compares, here stdout): SCHEMA-OUT-APPROVE and SCHEMA-OUT-FLAG list [8]; SCHEMA-LOOP-CONVERGE lists [8, 21, 34, 35, 39]; SCHEMA-LOOP-BRANCH lists [8, 21, 34, 35]; NEG-SCHEMA-LOOP lists the same as its target. Each delta's landing ticket extends the schema in the same change (ROADMAP schema staging).

## Decisions (human, 2026-10-08; binding)
1. Per-scope variants (option B) for loop_start, fix and loop_end. loop_start/working-tree: required {type, scope const "working-tree", fixerCmd, constraintMode, loopMax}, no branch/originalHead. loop_start/branch: required {type, scope const "branch", branch (minLength 1), fixerCmd, constraintMode, loopMax, originalHead}. fix/working-tree: required {type, iteration, fixerCmd, filesTargeted, filesModified, stashRef (string|null)}. fix/branch: required {type, iteration, fixerCmd, filesTargeted}, nothing else allowed. loop_end/working-tree: required {type, exitReason, iterations, stashRef (string|null)}, optional matchedIteration and fixerStderr, originalHead forbidden. loop_end/branch: required {type, exitReason, iterations, originalHead}, nothing else allowed. Variants are mutually exclusive through `required` plus `additionalProperties: false`, so every real event matches exactly one oneOf branch.
2. constraintMode is enum ["advisory", "bwrap"] in both loop_start variants.
3. resumeHint is {cli: enum ["codex","agy","claude","agent"], id: string minLength 1, command: string minLength 1}, all required, additionalProperties false.
4. matchedIteration (integer >= 1) and fixerStderr (string) stay optional on loop_end/working-tree and are NOT tied to exitReason.

VALIDATOR
src/schema-validate.js (validateAgainstSchema) supports type/required/properties/additionalProperties/enum/items/minimum/maximum/minLength, but no `oneOf`, `const`, or type arrays, and it is production code that must not change here. Write test/parity/helpers/schema-lite.mjs supporting exactly: type (string or array, incl.
